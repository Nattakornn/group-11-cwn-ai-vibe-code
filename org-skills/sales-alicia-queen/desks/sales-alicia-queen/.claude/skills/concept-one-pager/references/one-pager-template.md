## วิธีเขียนสมมติฐาน

- ใส่ไว้ในหัวข้อที่เกี่ยวข้อง ไม่แยกเป็นหัวข้อท้ายหน้า
- รูปแบบ: *[สมมติฐาน] <ประโยคที่ลูกค้าตอบใช่หรือไม่ใช่ได้>* ตัวเอียง สีเทา
- ✅ "*[สมมติฐาน] ระบบใช้ภายในองค์กรเท่านั้น ยังไม่เปิดให้ลูกค้าภายนอกใช้*"
- ❌ "ยังไม่แน่ใจเรื่องผู้ใช้" (ลูกค้าตอบไม่ได้)

## แนวตัดสินกรณีก้ำกึ่ง

| เจอในโน้ต | ทำอย่างไร | ตัวอย่าง |
|---|---|---|
| ช่องทางหรือความสามารถที่ลูกค้าระบุเองว่าต้องการ | ✅ ใส่ได้ เพราะเป็นความต้องการของลูกค้า ไม่ใช่ tech stack | "ดูสลิปผ่าน TTB Touch", "AI กรองตามระเบียบ", "เชื่อมข้อมูลกรมการปกครอง" |
| คำศัพท์มาตรฐานที่ลูกค้าใช้เอง | ✅ ใส่ได้ แต่ไม่ระบุชื่อเทคโนโลยี | "API Standard" → "เชื่อมข้อมูลด้วยมาตรฐานกลาง (API Standard)" |
| รูปแบบติดตั้งหรือโครงสร้างระบบ | 🚫 ไม่ใส่ แจ้งในแชตให้ส่ง SA | "On Premise", "ใช้ cloud" |
| ตัวเลขที่ขัดกันเอง | ❓ เขียนเป็น `[สมมติฐาน]` และระบุทั้งสองค่า | "เงินช่วยพิเศษ 10 เท่า" กับ "3–30 เท่า" |
| ตัวเลขสถิติที่ไม่ชัดว่าเป็นของกลุ่มไหน | ❓ เขียนเป็น `[สมมติฐาน]` เฉพาะตัวที่ตีความได้ ตัวที่ตีความไม่ได้ไม่ต้องใส่ | ตาราง Stats ที่หัวคอลัมน์ไม่ครบ |
| หัวข้อที่ลูกค้าไม่ได้บอกปัญหา แต่มี As is | ❓ อนุมานปัญหาจาก As is แล้วเขียนเป็น `[สมมติฐาน]` | "ทำเบิกได้รอบละ 16 ราย" → ปัญหาคือล่าช้า |
| งานที่เซลส์ต้องไปทำต่อ | 🚫 ไม่ใส่ แจ้งในแชตเป็น next step | "คุยกับแผนก IT หน่วยกรรมวิธีข้อมูล" |
| ชื่อหรือชื่อเล่นของผู้เข้าประชุม | 🚫 ไม่ใส่ ใช้ชื่อหน่วยงานแทน | "พี่เก", "ผอ.เบิร์ด" |
| ขอบเขตที่ลูกค้าบอกว่าทำทีหลัง | ✅ ใส่ในบรรทัด "นอกขอบเขตระยะนี้" | "ข้าราชการประจำทำ Phase 2" |
