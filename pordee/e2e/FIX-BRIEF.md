# คำสั่งทีมแก้เว็บ (รอบแก้บั๊ก) · ทุกทีมใช้ร่วมกัน

ตอนนี้คุณคือ **นักพัฒนาเว็บ** ไม่ใช่ tester: อ่าน/แก้โค้ดใน `web/` ได้ (ไม่ต้องแก้ `db/` ถ้าไม่จำเป็น ถ้าต้องแก้ schema/seed ให้แจ้งในรายงาน)

## เป้าหมาย
ทำให้ test ของทีมคุณใน `e2e/FIX-LIST.md` ผ่านในโหมดปกติ `BUG_MODE=0` โดยทำตามผลที่คาดหวังใน `TEST-PLAN.md` (การ์ดของ ID นั้น + สมมติฐาน 8.2) และ `REQUIREMENTS.md`

## ห้าม
- **ห้ามแก้ `e2e/` (test, fixture, แผน) และ `TEST-PLAN.md`** · ถ้าคิดว่า test/แผนผิด ให้เขียนในรายงาน ไม่ต้องแก้
- **ห้ามแตะบั๊กปริศนา:** ทุกจุดที่เรียก `modeFlag()` / `lib/bug.ts` ต้องทำงานเหมือนเดิมเมื่อ `BUG_MODE=1` (ดู `web/BUGS.md` ว่ามีอะไรบ้าง) · โหมดปกติต้องถูก
- ห้ามทำให้หน้า EN มีอักษรไทย · ห้ามใช้ JS number กับเงิน (ใช้ decimal.js ตาม lib/money)
- แก้เฉพาะไฟล์ที่เกี่ยวกับงานของทีม · ไฟล์กลาง (`lib/http.ts`, `lib/i18n.ts`, `messages/*`, `components/chrome.tsx`, `app/globals.css`) แก้ได้แบบเพิ่ม ไม่ลบ/เปลี่ยนของเดิมที่ทีมอื่นใช้ · ทีมอื่นแก้ไฟล์ใน `web/` พร้อมกับคุณ ถ้า build พังในไฟล์ที่ไม่ใช่ของคุณ รอสักครู่แล้วลองใหม่
- ห้าม build/restart `pordee-web` หลัก (:3300) และห้ามใช้เว็บชุดของทีมอื่น

## วงจรตรวจของทีม (ชุดของคุณ = N)
```bash
cd e2e && scripts/fix-shard.sh N        # build image pordee-web:fixN จาก web/ แล้วเปิดเว็บ :31N0 DB :31N1 (~2–4 นาที)
BASE_URL=http://localhost:31N0 DB_URL=postgres://pordee:pordee@localhost:31N1/pordee PW_OUT=test-report/raw/fixN \
  npx playwright test --project=chromium -g "TC-XXX-01|TC-XXX-02"
```
- รันเฉพาะ test ของทีม + test อื่นในไฟล์ spec เดียวกัน (ต้องไม่ทำให้ข้อที่เคยผ่านพัง) · `cd web && npx tsc --noEmit` ต้องผ่าน
- ห้ามรัน vitest (ใช้ DB กลาง ชนกัน) หัวหน้าจะรันตอนรวม
- ทำซ้ำได้จนผ่าน แต่ถ้าข้อใดติดเกิน 3 รอบ ให้หยุดและรายงานเหตุ

## ตอนจบ
- เพิ่มบันทึกสิ่งที่เปลี่ยนพฤติกรรมลง `web/SPEC.md` ส่วน 5 (หัวข้อ "รอบแก้บั๊ก · ทีม X") สั้น ๆ
- `scripts/shards.sh down "N"`
- รายงานกลับ ≤ 12 บรรทัด: ต่อ ID ผ่าน/ไม่ผ่าน · ไฟล์ที่แก้ · ข้อที่คิดว่าแผน/test ผิด
