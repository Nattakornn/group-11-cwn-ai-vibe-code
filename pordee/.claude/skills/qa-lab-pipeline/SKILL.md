# QA LAB pipeline · แผนที่รวม

ประโยคหลัก: **"ลูกค้าขอ ≠ AI บอกว่าทำแล้ว ≠ เว็บทำจริง"** งานของ tester คือพิสูจน์ ไม่ใช่เชื่อ

## ลำดับ และ skill ของแต่ละช่วง

| ช่วง | LAB | ได้ไฟล์ | skill |
|---|---|---|---|
| 🟢 ฟังลูกค้า | 1 User Story · 2 FR/BR/NFR · 3 Design · 4 Test data | `USER-STORIES.md` `REQUIREMENTS.md` `DESIGN.md` `design/` `TEST-DATA.md` | `lab-listen` |
| 🟡 สร้างเว็บ | 5 ใบสั่งงาน · 6 สร้างด้วย agent หลายตัว + ฝังบั๊ก | `BUILD-PROMPT.md` `db/` `web/` `web/SPEC.md` `web/BUGS.md` | `lab-build-web` |
| 🔵 สำรวจ | 7 charter · 8 สำรวจขนาน · 9 รวมผล + ผู้ตัดสินความเสี่ยง | `CHARTERS.md` `exploration/` `EXPLORATION.md` | `lab-explore` |
| 🟠 เขียนแผน | 10 writer ต่อหัวข้อย่อย · 11 ผู้รีวิวคนละชุด | `plan/` `TEST-PLAN.md` `review/` `PLAN-REVIEW.md` | `lab-test-plan` |
| 🟣 พิสูจน์ | 12 Playwright ขนาน + GIF + รายงาน · 13 บั๊กปริศนา | `e2e/index.html` `e2e/triage.json` `BUG-HUNT.md` | `lab-prove` |

ไฟล์ของ LAB ก่อนหน้าคือความจำของ LAB ถัดไป ทำตามลำดับ และอัปเดตตารางสถานะใน `../README.md` ทุกครั้งที่จบ LAB (ตัวเลขจริง เช่น จำนวน story, FR/BR, test, % ผ่าน)

## หาว่าตอนนี้อยู่ตรงไหน
ดูว่าไฟล์ไหนมีแล้ว (ตามตารางบน) และอ่านตารางสถานะใน `../README.md` · LAB ถัดไป = ไฟล์แรกที่ยังไม่มี · ถ้าผู้ใช้บอก "ทำต่อจนจบ" ให้ไล่ทำต่อเนื่องและรายงานสั้น ๆ หลังจบแต่ละ LAB

## กติกากลางที่ใช้ทุกช่วง (เหตุผลอยู่ในวงเล็บ)
- **ป้าย oracle ทุกค่าที่คาดหวัง:** `[D]` ลูกค้า/เอกสารสัมภาษณ์ · `[R]` กฎทั่วไป (เวลา เงิน ความปลอดภัย) · `[A]` สิ่งที่ AI ผู้สร้างอ้างใน SPEC · `[O]` สิ่งที่เห็นบนจอ (จะได้รู้ว่าค่ามาจากไหน ค่าที่ลอกจากจอจับบั๊กไม่ได้ — LAB 13 ของโปรเจกต์นี้ [O] จับได้ 0/3)
- **ห้ามอบบั๊กลงผลที่คาดหวัง:** คิดค่าจากกฎก่อนเปิดเว็บ ถ้าเว็บต่างจากแผน ปล่อยให้ล้มแล้วจำแนก ห้ามแก้ค่าตามจอ (ถ้าแผนผิดจริง แก้แผนอย่างเปิดเผย มีเหตุผลจาก [D]/[R])
- **ค่าขอบ ต่ำกว่า / ตรง / สูงกว่า** ทุกตัวเลขที่เป็นเกณฑ์ (โควตา เวลา เงิน)
- **คนตรวจไม่ใช่คนเขียน:** ผู้รีวิวแผน ผู้จำแนกข้อที่ล้ม และผู้ตัดสินความเสี่ยง เป็น agent ใหม่ที่ไม่ได้เขียนงานนั้น (กันการเข้าข้างงานตัวเอง)
- **tester ไม่อ่านโค้ด:** ตั้งแต่ LAB 7 คนทดสอบอ่านได้แค่ `web/SPEC.md` `web/ASSETS.md` · **ห้ามเปิด `web/BUGS.md` จนถึง LAB 13 ขั้นที่ 7**
- **test ที่ไม่มีวันล้ม แย่กว่า test ที่ล้ม:** ทุก test ต้องมี assert จริง ตรวจทุกจุดที่กฎกระทบ ไม่ใช่จุดเดียว
- **นับด้วยสคริปต์ ไม่นับด้วยมือ** (นับมือพลาดซ้ำหลายครั้งในโปรเจกต์นี้) · ตรวจตัวเลขสรุปทุกครั้งก่อนเขียนลงไฟล์
- **ทำงานแบบหลาย agent:** 1 agent ต่อ 1 ส่วนที่ไม่ทับกัน แต่ละตัวเขียนเฉพาะไฟล์ของตัวเอง · ถ้า agent หยุดเพราะ rate limit ให้ส่งข้อความปลุกตัวเดิม (SendMessage) แทนการสร้างใหม่ งานที่ทำไว้ยังอยู่

## สภาพแวดล้อมของโปรเจกต์นี้
- เว็บ http://localhost:3300 · DB 127.0.0.1:5434 (pordee/pordee) · Docker 2 โปรเจกต์บน network `pordee-net` · พอร์ต 3000 ถูก container อื่นใช้
- API ทดสอบ (`ALLOW_TEST_API=1`): `/api/test/reset {now?}` (ค่าเริ่ม = วันล็อก 2026-11-06T22:00:00+07:00) · `/clock` · `/feed` · `/tick` · `/api/health`
- โหมดบั๊ก: `cd web && BUG_MODE=1 docker compose up -d` (ไม่ต้อง build) · ตรวจ `<html data-bug-mode>` · จบแล้วคืนเป็น 0 เสมอ
